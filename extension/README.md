# 니케 컴패니언 연결 (크롬 확장)

이미 blablalink에 로그인돼 있는 브라우저의 세션을 **단추 한 번**으로 니케 컴패니언 오버레이에 넘긴다(P-025).
자동 로그인(SSO)으로 쓰느라 비밀번호를 모르는 계정도 받을 수 있다 — 앱 안의 로그인 창에서 다시 로그인할 필요가 없다.

- 누를 때만 동작한다. 백그라운드에서 돌지 않는다(서비스 워커·콘텐츠 스크립트가 없다).
- 읽는 것: `api.blablalink.com` 요청에 실릴 쿠키. 다른 사이트의 쿠키·탭 내용·방문 기록에는 권한이 없다.
- 보내는 곳: 이 PC의 오버레이(`http://127.0.0.1:47615`) 하나. 다른 곳에 보내지 않고, 쿠키를 저장하지 않는다.

오버레이 쪽 설명(수신부·연결 코드·보안 규칙)은 `app/README.md` §크롬 확장으로 계정 받기.

## 설치 (한 번)

크롬 웹 스토어에 올리지 않는다 — 이 폴더를 직접 불러온다.

1. 크롬에서 `chrome://extensions`를 연다(엣지는 `edge://extensions`).
2. 오른쪽 위의 **개발자 모드**를 켠다.
3. 앱의 설정 → 계정 연결 → **확장 설치(한 번)**에서 **확장 폴더 열기**로 위치를 확인한다. **경로 복사**를 누른 뒤 브라우저에서 **압축해제된 확장 프로그램을 로드합니다**를 누르고 복사한 위치를 붙여 넣는다. 설치판에서는 앱 설치 폴더의 `extension`, 저장소에서는 저장소의 `extension`이다.
4. 도구 모음의 퍼즐 조각 아이콘에서 「니케 컴패니언 연결」을 고정해 두면 편하다.

패스키로 로그인하는 브라우저 프로필에 설치한다. 배포된 v0.1.0에는 확장 폴더가 없다.
설치판을 업데이트하거나 저장소의 확장을 고친 뒤에는 `chrome://extensions`에서 그
확장의 새로 고침(↻)을 눌러 다시 로드해야 반영된다.

## 연결 (한 번)

1. 오버레이의 **계정** 탭 → 「방법 1 · 크롬 확장」에서 **크롬 확장 연결**을 켠다. 연결 코드(`ABCD-EFGH` 꼴 여덟 글자)가 보인다.
2. 확장 아이콘을 눌러 팝업의 **연결 코드** 칸에 그 코드를 넣는다. 한 번 넣으면 기억한다(팝업의 저장소 — 쿠키가 아니다).

오버레이에서 「코드 다시 만들기」를 누르면 옛 코드는 그 순간부터 받지 않는다 — 확장에 새 코드를 넣는다.

## 쓰기

1. 앱의 설정 → 계정 연결에서 **브라우저로 로그인**을 누른다. 크롬 확장 연결이 켜지고 기본 브라우저가 열린다.
2. 열린 브라우저 프로필에서 평소 쓰는 패스키로 로그인한다. 이미 로그인돼 있으면 연동된 게임 계정을 확인한다.
3. 확장 아이콘 → **오버레이로 보내기**.

팝업의 상태 줄에 결과가 나온다.

| 상태 줄 | 뜻 | 할 일 |
|---|---|---|
| 오버레이가 받았다 | 오버레이가 쿠키를 저장했고 계정 받기(수집 → 변환 → 저장)를 이어서 돌린다 | 오버레이의 계정 화면에서 진행을 본다 |
| 오버레이가 꺼져 있다 | 127.0.0.1의 수신부에 연결되지 않는다 | 오버레이를 켜고 계정 화면에서 「크롬 확장 연결」을 켠다 |
| 연결 코드가 틀리다 | 팝업의 코드가 오버레이의 코드와 다르다 | 오버레이 계정 화면의 코드를 다시 넣는다 |
| 코드를 여러 번 틀려 … 잠시 막았다 | 연속 다섯 번 틀리면 1분 동안 모든 요청을 막는다 | 코드를 고치고 남은 시간 뒤에 다시 누른다 |
| blablalink에 로그인돼 있지 않다 | `game_token`·`game_openid` 쿠키가 없다 — **아무것도 보내지 않았다** | 이 브라우저에서 blablalink.com에 로그인하고 게임 계정을 연동한다 |
| 연결 코드를 먼저 넣어라 | 코드 칸이 비었거나 모양이 다르다 — 쿠키를 읽지도 않았다 | 코드를 넣는다 |
| 오버레이가 지금 계정을 받는 중이다 | 수집이 도는 동안에는 쿠키를 바꾸지 않는다 | 끝난 뒤에 다시 누른다 |
| 오버레이가 아닌 답이 왔다 | 그 포트에서 다른 프로그램이 답했다 | 오버레이 계정 화면에 보이는 문제를 확인한다 |

## 권한과 보안

`manifest.json`의 권한은 이것뿐이다(`tests/manifest.test.mjs`가 파일을 읽어 확인한다).

| 권한 | 왜 |
|---|---|
| `cookies` | `chrome.cookies.getAll({ url: "https://api.blablalink.com/api/game/proxy/" })` — 그 주소로 가는 요청에 실릴 쿠키를 묻는다 |
| 호스트 `https://*.blablalink.com/*` | 쿠키 API는 호스트 권한이 있는 사이트의 쿠키만 준다 — blablalink 것만 읽을 수 있다 |
| 호스트 `http://127.0.0.1/*` | 이 PC의 오버레이에 요청을 보낸다(포트를 적지 않은 패턴은 모든 포트에 맞는다. 코드가 보내는 곳은 `:47615` 하나다) |

- `tabs`·`history`·`scripting`·`storage`·`webRequest` 같은 권한이 없다. 모든 사이트(`<all_urls>`)에 걸리는 호스트 권한도 없다.
  선택 권한(`optional_*`)도 없어 나중에 더 받아 낼 길이 없다.
- 백그라운드 서비스 워커·콘텐츠 스크립트·타이머·알람이 없다. 코드가 도는 것은 팝업이 열려 있는 동안뿐이고, 쿠키를 읽는 곳은
  단추의 클릭 처리 한 줄이다.
- 쿠키는 팝업의 지역 변수로 있다가 요청 한 번에 실려 가고 사라진다. `localStorage`에 쓰는 것은 연결 코드 하나다. 로그를 남기지
  않는다(`console.*` 없음).
- 보내는 요청: `POST http://127.0.0.1:47615/nikke-companion/v1/session`, `Content-Type: application/json`,
  본문 `{"code": "<연결 코드>", "cookie": "<Cookie 헤더 한 줄>"}`. 브라우저의 쿠키·리퍼러는 얹지 않는다
  (`credentials: "omit"`, `referrerPolicy: "no-referrer"`), 리디렉션은 따라가지 않는다(`redirect: "error"`).
- 평문 HTTP지만 루프백을 벗어나지 않는다 — 이 PC 안에서만 오간다. 오버레이의 수신부는 127.0.0.1에만 묶여 있고, 연결 코드가
  맞고 출처가 크롬 확장인 요청만 받는다(웹 페이지는 부르지 못한다).
- 쿠키 목록 → 헤더 한 줄은 `lib/cookie-header.js`(순수 모듈)가 만든다: 도메인이 `api.blablalink.com`이나 그 윗도메인인 쿠키만,
  `이름=값` 꼴로 쓸 수 있는 것만. 오버레이가 받은 뒤 같은 검사를 한 번 더 한다.

연결 코드는 앱이 확장의 요청을 검사할 때 쓴다. 앱이 꺼져 있고 다른 로컬 프로그램이 같은 포트를 사용하면, 확장은 전송 전에 이를 구별할 수 없다.
확장이 받는 쪽이 니케 컴패니언인지 확인할 수 없어 자동 전달은 보류했다. 앱이 확장에 자신을 증명하는 방식을 사용자가 정하면 별도 작업으로 재개한다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `manifest.json` | Manifest V3. 권한 셋, 팝업 하나 |
| `popup.html` · `popup.css` · `popup.js` | 팝업: 연결 코드 칸, 「오버레이로 보내기」 단추, 상태 한 줄. `popup.js`는 접착 코드다 |
| `lib/cookie-header.js` | 쿠키 목록 → Cookie 헤더 한 줄(순수). 도메인 판정, 필수 쿠키 확인 |
| `lib/link.js` | 단추 한 번에 하는 일 전체(`sendSession`) — chrome API와 `fetch`는 밖에서 받는다. 오버레이의 답 → 안내 문장 |
| `package.json` | Node가 `lib/*.js`를 ES 모듈로 읽게 한다(테스트용). 의존성 없음 |
| `tests/` | `node --test`로 도는 테스트(브라우저 없이) |

## 테스트

```bash
node --test extension/
```

브라우저도 오버레이도 띄우지 않는다. 쿠키는 지어낸 값이고 요청은 가짜다.

- `tests/cookie-header.test.mjs` — 도메인이 맞는 것만 쓴다, 필수 쿠키가 없으면 만들지 않는다, 쓸 수 없는 쿠키는 뺀다
- `tests/link.test.mjs` — 로그인돼 있으면 한 번 보낸다(보내는 본문·주소 확인), 로그인돼 있지 않으면 보내지 않는다, 코드가 없으면
  쿠키를 읽지도 않는다, 「받았다 / 꺼져 있다 / 코드가 틀리다 / 로그인돼 있지 않다」가 구분된다, 결과에 쿠키가 없다
- `tests/manifest.test.mjs` — 권한이 그 셋뿐이다, 백그라운드·콘텐츠 스크립트가 없다, 쿠키를 읽는 곳·보내는 곳·저장하는 것이
  각각 한 곳이다
- `tests/contract.test.mjs` — 포트·경로·코드 글자·답의 사유·쿠키 규칙이 오버레이의 Rust 쪽(`app/src-tauri/src/extension_link.rs`·
  `cookie.rs`)과 같다

## 한계

- **크로뮴 계열 브라우저**(크롬·엣지·웨일·브레이브)에서만 쓴다. 오버레이는 출처가 `chrome-extension://…`인 요청만 받는다 —
  파이어폭스는 확장의 출처와 API가 달라 지원하지 않는다. 크롬 말고는 써 보지 않았다.
- 포트는 47615로 고정이다. 다른 프로그램이 그 포트를 쓰고 있으면 오버레이가 「크롬 확장 연결」을 켜지 못하고 그 사실을 알린다.
- 브라우저 프로필마다 쿠키가 따로다. blablalink에 로그인한 그 프로필에 확장을 설치한다. 시크릿 창에서는 기본적으로 확장이 꺼져 있다.
- 개발자 모드로 불러온 확장이라 크롬이 시작할 때 「개발자 모드 확장 프로그램 사용 중지」 알림을 띄울 수 있다(그대로 둔다).
- 아이콘이 없다(크롬이 이름의 첫 글자를 보인다).
- 받는 계정은 그 브라우저에 로그인돼 있는 blablalink 계정 하나다.

## 사람이 확인할 것 (아직 확인하지 않았다)

이 확장은 **실제 크롬에 설치해 본 적이 없다** — 자동 테스트는 Node에서 가짜 쿠키·가짜 요청으로만 돈다(에이전트는 사용자의
크롬에 확장을 설치하거나 실제 blablalink에 로그인하지 않는다). 아래는 사람이 확인한다.

- 확장이 오류 없이 로드되는가(`chrome://extensions`에 오류 단추가 없는가).
- 연결 코드를 넣고, blablalink에 로그인된 상태에서 단추 한 번으로 오버레이의 계정 받기가 끝까지 가는가.
- 로그인돼 있지 않을 때·오버레이가 꺼져 있을 때·코드가 틀릴 때 상태 줄의 안내가 맞는가.
- 가정 둘 — 틀리면 오버레이가 요청을 거부한다(팝업에 「오버레이가 아닌 답이 왔다 (origin)」처럼 사유가 보인다):
  - 확장의 팝업이 보내는 POST에 브라우저가 `Origin: chrome-extension://<확장 ID>`를 붙인다.
  - 호스트 권한 `http://127.0.0.1/*`가 `:47615`에도 맞아, 브라우저가 사전 요청(OPTIONS) 없이 요청을 그대로 보낸다
    (수신부는 사전 요청에 허용 헤더를 주지 않는다).
- `chrome.cookies.getAll({ url })`이 `game_token`·`game_openid`를 돌려주는가(쿠키가 `api.blablalink.com` 요청에 실리는
  도메인·경로로 심겨 있어야 한다 — 실제 쿠키의 도메인은 확인하지 못했다).
