# UI 개편 — 데스크톱 앱 + 오버레이

UI 개편 세 작업(P-026 디자인 기반 → P-027 데스크톱 앱 창 → P-028 오버레이 위젯)의 기준 문서다.
P-027·P-028은 이 문서를 따른다. 구조나 원칙을 바꿔야 하면 이 문서를 먼저 고친다.

상태: **세 작업을 모두 만들었다(P-028 — 오버레이 위젯까지).** 그 뒤에 P-029(요격전 계획 — §4c)와 P-030(덱 빌더 — §4d)이 화면을 더했다. P-026이 디자인 기반(이 문서, 토큰, 이미지 명령, 공통 부품, 한 줄 요약,
남은 시간 어림, 리소스 받기 스크립트)을, P-027이 데스크톱 앱 창(왼쪽 메뉴와 화면 여섯, 두 창이 같은 결과를 보는 바탕)을, P-028이
오버레이 위젯(모양 셋·자동 표시·위젯만 한 창·자리 기억·오버레이 설정)을 만들었다 — 만든 것과 시안에서 달라진 것은 §4a·§4b에 적었다.
**실제 게임 위에서 눈으로 본 것은 아직 없다**(§15).

## 1. 배경

사용자가 오버레이를 실제로 써 보고 말했다(2026-11-12):

- "일반 사용자는 보고 알 수가 없다. 시각화 중심으로 전부 바꿔야 한다."
- "캐릭터 이미지와 보스 이미지를 쓰고, 더 트렌디하고 컴팩트하게."
- "Blitz(<https://blitz.gg/lol/overlays>)와 OP.GG 데스크톱(<https://op.gg/desktop/ko/games/lol>)을 참고해
  **데스크톱 앱을 만들고 오버레이를 붙이는 구조**로."
- "리소스는 게임 리소스에서 뽑아서 쓰라."(→ §7·§8 — 허용되는 출처는 둘뿐이다)

같은 날 대화에서 시안을 보였고 사용자가 확인했다("이 구조로 진행").

두 참고 사이트에서 가져온 것(대화형 세션이 본 것을 작업 설명에 적어 둔 내용이다): 본체는 **일반 창의 데스크톱 앱**이다 —
초상화가 든 촘촘한 목록, 색 배지와 막대, 보라 계열 강조색, 왼쪽 아이콘 메뉴. **오버레이는 한 가지 일만 하는 작은 조각**이다.
가져오는 것은 구조와 표현 방식이다. 코드·이미지·데이터는 가져오지 않는다.

지금까지의 화면이 왜 읽히지 않았나: 파일 경로 입력 칸이 맨 위에 있고, 결과는 숫자 표이며, 경고·계산 조건이 결과와 같은 크기로
섞여 있고, 문구가 개발 용어(파일·JSON·시뮬·예산)다.

## 2. 구조

| | 데스크톱 앱 | 오버레이 |
|---|---|---|
| 창 | 일반 창(테두리·작업 표시줄에 보임), 어두운 불투명 배경 | 게임 위에 뜨는 작은 위젯(테두리 없음·항상 위) |
| 하는 일 | **전부** — 계정 연결, 계산 실행, 설정, 결과 보기 | **결과만 보여 준다** |
| 탐색 | 왼쪽 아이콘 메뉴: 홈 · 요격전 · 내 니케 · 편성 도구 · 티어 · 설정 | 없음(게임에서 보고 있는 보스를 따라간다) |
| 만드는 작업 | P-027 | P-028 |

오버레이가 보여 주는 것: 보스 이미지·이름·약점·총딜·초상화 5장 한 줄. 접으면 보스 이름과 총딜만.
오버레이에는 입력 칸·실행 단추·설정이 없다 — 그런 것은 데스크톱 앱에서 한다.

## 3. 원칙

1. **파일 경로 입력 칸을 없앤다.** 계정은 한 번 연결하면 기억하고, 보스 값은 내장한다(`data/intercept/anomaly.json`).
2. **숫자 표 대신 타일·막대·배지.** 멤버별 딜은 초상화 타일 아래의 막대와 %로, 상태는 색 알약으로.
3. **맨 위에 한 줄 요약 문장.** 결과를 읽지 않아도 무엇이 핵심인지 알 수 있게(§9).
4. **경고와 계산 조건은 접어 둔다. 단 「추정 · 실전 미대조」는 항상 보인다.**
5. **정보 영역은 불투명 카드.** 게임 화면이 비쳐 글자가 묻히지 않게.
6. **한국어 문구는 게임 용어만 쓴다.** 개발 용어(파일·JSON·시뮬·예산)는 쓰지 않는다(§13).
7. **숨기면 안 되는 것(프로젝트 원칙 — `docs/spec.md` §4):** 미확인 값, 미지원 효과, 검증용 데이터 표시.
   눈에 띄는 배지로 **줄이되 없애지 않는다.** 접는 구획 안에만 넣는 것은 숨기는 것이다 — 배지는 접힌 구획 밖에 둔다.
8. **모르는 것은 「모름」이다.** 초상화가 없으면 이름 첫 글자, 속성을 모르면 회색 「?」, 총딜을 아직 모르면 「계산 전」 —
   0이나 그럴듯한 값으로 채우지 않는다.

### 4a. 데스크톱 앱 창 — 만든 것 (P-027)

자세한 것은 `app/README.md` §창 둘 — 데스크톱 앱과 오버레이. 여기에는 정한 것과 시안에서 달라진 것만 적는다.

정한 것:

- **앱 창을 닫으면 앱이 끝난다.** 트레이 아이콘이 없어 오버레이만 남기면 다시 열 길이 없는 프로세스가 된다. 오버레이 창은 닫히지
  않고 숨는다(앱 창이 떠 있는 동안 다시 띄울 수 있게).
- **오버레이를 띄우는 때**는 셋 중 하나다: 앱과 함께(기본) · 게임을 찾았을 때 · 직접. 디스크에 기억한다.
- **두 창이 같은 것을 본다**: 기본 계정의 이름·오버레이 설정·마지막 요격전 결과를 계정 폴더(gitignore)의 두 파일에 두고, 앱 창이
  저장하면 Rust가 모든 창에 알린다. 권한은 창마다 따로다(오버레이는 결과 읽기·창 조작뿐).
- **정밀도**는 빠르게 · 보통 · 꼼꼼히(계산 횟수의 상한 — 요격전 60·150·300건, 편성 도구의 추천 40·80·120건)이고 옆에 대략 걸리는
  시간을 적는다(한 건에 약 1.2초로 어림).
- **메뉴의 아이콘**은 직접 그린 도형 여섯이다(게임 이미지가 아니다).

시안·§4의 표와 달라진 것:

| 시안 | 만든 것 | 왜 |
|---|---|---|
| 홈에 「오늘 볼 것」 | 체크리스트 넷 + 다음에 할 일 단추 하나 + (추천이 있으면) 보스 5종 카드와 마지막 계산 시각 | 작업의 수락 조건이 체크리스트와 단추 하나를 요구했다. 「오늘 볼 것」의 내용은 보스 카드 줄이다 |
| 편성 도구에서 비교·성장을 실행 | 추천만 단추 하나로 실행한다. 비교·성장은 고급에서 계산하거나 불러온 결과를 타일·막대로 보여 준다 | 견줄 편성·육성 선택지를 화면에서 고르는 부품(덱 빌더)이 아직 없다 — P-030. 그때까지 고르는 길은 파일뿐이고, 파일을 고르는 곳은 고급에만 둔다 |
| 티어 화면에서 바로 보기 | 고급에서 한 번 불러온 표를 기억했다가 다시 연다 | 앱 안에서 티어를 계산하지 않는다(전원 계산은 수십 분 — 명령줄) |
| 예전 화면을 새 부품으로 다시 그림 | 예전 화면 넷은 **설정 > 고급**에 예전 모양(표)으로 남기고, 같은 결과를 새 그림(`src/views/`)이 타일·막대·배지로 그린다 | 고급은 파일 경로·건수 같은 개발 용어를 쓸 수밖에 없는 곳이다. 표에는 타일에 없는 숫자(원값·건수)가 있어 없애지 않았다 |
| 접힌 줄 밖의 배지 | 그대로 — 그리고 편성별 메모(자리 순서를 어떻게 바꿨는지 등)는 「계산 조건」 안에 넣었다 | 그 문장은 계산 코드가 만든 것이라 개발 용어가 섞여 있다. 한 줄 요약이 같은 내용을 쉬운 말로 한다 |
| 오버레이는 작은 위젯 | 결과만 보여 주는 창이 됐다(입력·실행·설정 없음). 그림은 앱 창과 같은 것을 작은 타일로 그린다 | 펼침·접힘 위젯은 P-028(§4b) |

### 4b. 오버레이 위젯 — 만든 것 (P-028)

자세한 것은 `app/README.md` §오버레이 위젯. 여기에는 정한 것과 위의 틀에서 달라진 것만 적는다.

**모양은 셋이다**(작업 설명의 시안 — 위 표의 「펼침」이 둘로 나뉘었다):

| 모양 | 보여 주는 것 |
|---|---|
| 접힘(알약) | 보스 얼굴 · 이름 · 총딜 · 「추정」. 내용만큼만 넓다 |
| 한 줄 카드(기본) | 보스 얼굴 44px · 이름 · 「약점 ○○」 · 총딜 · 「추정」 · 작은 초상화 5장(36px — 버스트 배지, 약점 속성 니케는 속성 색 테두리, 이름은 풍선 도움말). 아랫줄에 어느 계정·언제의 결과인지와 단추 셋(고정·접기·숨기기). 폭 480px |
| 펼침 | 한 줄 카드 + 한 줄 요약(§9) + 미확인 값·속성 상성 미반영·검증용 배지 + 자리 순서(1~5번 — 작은 타일 `sm`에 이름과 딜 비중) + 2·3위(순위 줄) + 보스 고르기 + 단축키 안내 |

정한 것:

- **누르거나 단축키(`Alt+Shift+M`)로 오간다.** 지금 모양·핀·쉬는 중·설정은 Rust가 쥔다(단축키와 자동 표시가 화면 없이도 바꾼다).
- **창은 위젯만큼만 크다.** 화면이 위젯의 크기를 재서 알리면 Rust가 창 크기를 맞춘다 — 빈 투명 영역이 게임 클릭을 가로막지 않는다.
  붙어 있는 모서리는 제자리다(오른쪽 위에 둔 위젯은 왼쪽·아래로 자란다).
- **자동 표시의 규칙은 Rust의 순수 함수 하나다**(`overlay_widget::AutoShow::step`): 이상 개체 화면+보스를 보면 되돌리고, 떠나면 설정한
  시간 뒤 접거나 쉬고, 핀이면 그대로, 모르는 동안(unknown·읽기 실패)에는 바꾸지 않고, 사용자가 손댄 것은 되돌리지 않는다.
  「쉰다」(창을 숨긴다)는 사용자가 숨긴 것과 달라, 쉬는 동안에도 자동 추적은 계속 읽는다.
- **결과가 없으면 한 줄과 「앱 열기」뿐이다**(계정 없음 · 아직 계산 안 함 · 보고 있는 보스가 결과에 없음 · 앱에서 계산 중 — 진행 막대와
  남은 시간 어림). 오버레이는 계산을 시작하지도 멈추지도 못한다.
- **보고 있는 보스가 결과에 없으면 다른 보스의 편성을 대신 보이지 않는다**(P-027까지는 앞의 보스를 그대로 보이며 한 줄로 알렸다 —
  작은 위젯에서는 편성만 보고 그 보스의 것으로 읽기 쉽다).
- **오버레이의 `×`는 숨기기다. 끝내기 명령을 없앴다**(§14의 「그때 다시 본다」의 답). 앱은 앱 창을 닫아 끝낸다 — 게임 위의 작은
  단추가 앱 창에서 돌던 계산까지 끝내면 안 된다. 숨긴 오버레이는 앱 창의 설정·홈이나 `Alt+Shift+O`로 다시 띄운다.
- **자리**는 끌어서 옮기고 기억한다: 화면 위의 자리, 붙이기를 켰으면 게임 화면의 가까운 모서리에서 잰 거리. 화면 밖이면 안쪽으로 되돌린다.
- **설정은 앱 창에 있다**(설정 > 오버레이): 기본 모양 · 크기 배율(80~150%) · 불투명도(40~100%, 기본 불투명 — 원칙 5) · 자동 숨김
  (그대로 두기 · 접기 · 숨기기, 2~120초) · 클릭 통과 · 자리 초기화.

위의 틀에서 달라진 것:

| 처음 잡은 틀 | 만든 것 | 왜 |
|---|---|---|
| 펼침·접힘 둘 | 접힘·한 줄 카드·펼침 셋 | 작업의 수락 조건(시안의 한 줄 카드가 기본이고, 요약·2·3위·자리 순서는 펼쳤을 때만) |
| 폭 320px부터, 작은 타일(`sm` 52px) 다섯 한 줄 | 한 줄 카드는 폭 480px에 더 작은 타일(`mini` 36px) 다섯, 펼침의 자리 순서 줄이 `sm` 다섯 | 보스 얼굴·이름·총딜과 초상화 다섯을 **한 줄**에 두려면 타일이 더 작아야 하고 폭이 더 필요하다(440px로 해 보니 이름 칸이 44px밖에 남지 않았다 — 실제 창을 찍어 확인). 좁게 쓰려면 크기 배율(80% → 384px)이나 접힘(244px쯤)을 쓴다 |
| 접힘은 보스 이름과 총딜만 | 보스 얼굴도 있다. 「추정」 알약도 남는다 | 수락 조건(보스 이미지·이름·총딜) + 원칙 4(「추정」은 항상 보인다) |
| 빈 상태 부품(`EmptyState`) | 한 줄 알림(글 + 「앱 열기」) | 위젯에 세 줄짜리 상자는 크다. 한마디와 무엇을 하면 되는지는 한 줄에 함께 적는다 |
| 미확인·검증용 배지는 접힌 구획 밖 | 펼침에서 배지로, 한 줄 카드에는 「확인할 표시 N개」로 줄여서, 알약에는 풍선 도움말로 | 한 줄에 다 넣을 수 없다 — 줄이되 없애지 않는다(원칙 7). 알약만은 「추정」 하나만 보인다 |

### 4c. 요격전 계획 — 새 구획 (P-029)

자세한 것은 `app/README.md` §요격전 계획, 규칙은 `docs/data-model.md` §요격전 계획. 커뮤니티 도구 모음의 기능(장비 현황표 · 진행 중인
콘텐츠 카드 · 기록 시트 · 육성 비교)에서 **생각만** 참고해 이 앱의 요격전 흐름에 맞는 것을 넣었다. 새 화면을 만들지 않고 있던 화면
셋에 구획을 더했다(왼쪽 메뉴는 그대로 여섯이다).

| 화면 | 새 구획 | 그림 |
|---|---|---|
| 홈 | **오늘의 요격전** 카드(계정이 있을 때) — 오늘 돌 보스 한 줄 · 그 보스의 1위 편성 초상화 다섯(`mini`)과 「추정」 · 지난 기록. 카드 전체가 단추다(요격전 화면의 그 보스로) | `views/TodayCard.vue` |
| 내 니케 | 위에 보기 둘 — 「니케」(예전 격자 + 타일마다 즐겨찾기 별) · **「장비 · 요격전 계획」**: ① 오늘 돌 보스(큰 한 문장 · 주력 기준 한 줄 · 보스별 필요 칸 수 막대 · 접어 둔 「근거」) ② 장비 현황(부위별·기업별 칩, 초상화(`xs`) 옆 네 칸 — 칸의 색: 미장착 빨강 · 일반 등급 주황 · 기업 장비 노랑 · 오버로드 초록 · 기록 없음/미확인 회색, 주력만/전체) ③ 속성 커버리지(속성 칩 · 그 속성이 약점인 보스 · 속성 색 막대 · N명) | `views/PlanBoard.vue` |
| 요격전 | 고른 보스의 편성 아래 **「내 기록」** — 추정과 기록을 나란히 + 차이 배지, 입력 한 줄(대미지 · 모의전/실전 · 날짜 · 달성 단계 · 「기록 적기」), 기록 목록. 맨 위 배지는 기록이 있으면 「추정 · 기록과 ○○% 차이」 | `views/RecordPanel.vue` · `views/InterceptResult.vue` |

원칙과의 관계:

- 원칙 2(표 대신 타일·막대·배지): 장비 현황은 표가 아니라 초상화 + 색 칸 넷, 보스별 필요 칸 수와 커버리지는 막대다. 색만으로 알리지
  않는다(칸마다 「미장착」·「T9 일반」·「오버로드 +5」 글자가 있다).
- 원칙 3(한 줄 요약): 「머리 장비가 가장 급하다 → 울트라」가 맨 위다. 근거는 접어 둔다.
- 원칙 4(「추정 · 실전 미대조」는 항상 보인다): 기록이 있어도 **「추정」은 남는다** — 「추정 · 기록과 12% 차이」. 기록에 맞춰 수치를
  고치지 않으므로 여전히 추정이다.
- 원칙 7·8(숨기지 않는다 · 모르는 것은 모름): 「보상이 나올 확률과 한 번에 얻는 수는 모른다」·「끼지 않은 장비의 수는 계정 정보에
  없다」·「장비가 계정에 적혀 있지 않은 니케 N명은 세지 않았다」는 접힌 구획 **밖**의 문장이다. 장비 기록이 없는 칸은 미장착이 아니라
  회색 「기록 없음」이다.
- 입력 칸: 요격전 화면에 처음으로 입력 칸(기록)이 생겼다. 파일 경로를 묻는 칸은 여전히 없다(원칙 1).

확인하지 못한 것: 실제 창에서의 모습(네 칸이 좁은 창에서 줄을 넘는지, 초상화가 많은 「전체」 목록의 속도), 실제 계정에서 문장이
납득이 가는지 — §15와 `app/README.md` §요격전 계획 §한계.

### 4d. 덱 빌더 — 새 탭 (P-030)

자세한 것은 `app/README.md` §덱 빌더, 규칙은 `docs/data-model.md` §덱 빌더. 커뮤니티 도구 모음의 편성 화면들(약점 선택 · 내 편성
01~05 · 덱 계산 · 「한 명을 바꾼다면?」 · 스펙 기준 전환 · 다섯 자리에 초상화를 놓는 팀 빌더)에서 **생각만** 참고했다. 편성 도구에
탭 하나(「덱 빌더」)를 더했다 — 왼쪽 메뉴는 그대로 여섯이다. §4a의 표에서 「견줄 편성을 화면에서 고르는 부품이 아직 없다」던 자리다.

위에서 아래로:

| 구획 | 그림 | 부품 |
|---|---|---|
| **상대** | 세 줄의 고르기 단추 — 이상 개체(보스 다섯, 「약점 ○○」) · 솔로 레이드(계산 도구에 든 보스) · 속성만 정하기(약점 다섯 + 속성 없음). 아래에 고른 상대: 이름 · 약점 칩 · 「속성 상성 미반영」 · **「미확인 값 N칸」**(요격전 화면과 같은 배지·같은 풍선 도움말) · 「검증용 보스 정보」 | `views/DeckOpponent.vue` |

| **편성** | 다섯 자리(1번~5번): 큰 타일(`lg` — 버스트 배지·속성 점·약점 테두리·**딜 비중 막대**), ◀ · 빼기 · ▶, 「바꿔 본다면」. 자리끼리 끌어 맞바꾼다. 아래에 버스트 단계 구성 한 줄(모자라면 무엇이 없는지 — 다 찼는데 모자라면 경고색). 오른쪽 위에 「자리 순서 비교」 | `views/DeckBuilder.vue` |

| 접어 둔 **계산 조건** | 상대의 메모 · 미확인 값의 칸별 내용 · 가정 · 「모두 최대 육성」의 뜻 · 주의 · 계산 정보 | `DetailsFold` |

요격전 화면의 편성 옆에는 **「덱 빌더에서 열기」** 단추가 생겼다(지금 보고 있는 순위의 편성이 자리 순서 그대로, 그 보스를 상대로 온다).
설정 > 계산 도구에는 **「다섯 자리가 차면 바로 계산한다」**(기본 꺼짐)가 생겼다.

원칙과의 관계:

- 원칙 1(파일 경로 없음): 계정은 기본 계정, 보스 값은 내장 묶음, 상대는 단추로 고른다. 입력 칸은 이름 찾기와 저장할 이름뿐이다.
- 원칙 2·3: 결과는 큰 숫자 하나 + 타일의 막대. 두 기준의 비교는 표가 아니라 나란한 두 상자와 한 문장이다.
- 원칙 4·7: 「추정 · 실전 미대조」는 계산 전에도 보인다. 미확인 값·속성 상성 미반영·검증용 표시는 접힌 구획 밖이다. **계산하지 못한
  편성은 0이 아니라 「계산하지 못함」** 배지이고, 「한 명을 바꾼다면」에서 상한 때문에 못 본 니케와 계산하지 못한 니케도 접지 않는다.
- 원칙 6: 「엔진 기본 스펙」은 화면에서 「계산 도구의 기본 스펙」이다. 「배치 변형」은 「자리 순서」, 「상한」은 「한 번에 N명까지」.
- 원칙 8: 솔로 레이드 보스의 약점은 이 화면이 모른다(계산 도구 안의 값이다) — 「약점 속성은 이 화면이 알지 못한다」고 적고
  약점 테두리를 그리지 않는다. 저장한 편성의 총딜은 계산하지 않았으면 「계산 전」이다.
- 「모두 최대 육성」은 **전부 최대가 아니다**(코어 강화 0) — 풍선 도움말과 계산 조건에 적는다. 이름은 작업이 정한 것을 따랐다.

확인하지 못한 것: 실제 창에서의 모습(다섯 자리의 폭, 끌어다 놓기의 느낌, 121명 계정의 격자), 실제 계정에서 한 명 바꾸기·자리 순서
비교가 납득이 가는지 — §15와 `app/README.md` §덱 빌더 §한계.

## 7. 이미지와 아이콘

화면에는 파일·네트워크 권한이 없다. 이미지는 **Rust 명령이 이 PC의 파일에서 읽어** base64로 넘기고(`app/src-tauri/src/assets.rs`),
화면은 `data:` 주소로 그린다(CSP는 그대로 — `img-src 'self' data:`). 네트워크 권한을 더하지 않았다.

| 명령 | 화면이 넘기는 것 | 읽는 조건 | 읽는 순서 |
|---|---|---|---|
| `nikke_portrait(name)` | 니케 이름 | 이름이 **엔진 카탈로그**(`data/parsed_nikke.json`)에 있을 때만 | 엔진 폴더 `image/<이름>.webp` → `data/assets/portraits/<이름>.webp` |
| `boss_image(id)` | 보스 id | id가 **내장 보스 묶음**(`data/intercept/anomaly.json`)에 있고 `a-z 0-9 _ -`뿐일 때만 | `data/assets/bosses/<id>.webp`·`.png` → `data/captures/bosses/<id>.png` |
| `game_icon(kind, key)` | 종류와 값 | **아이콘 표**(`assets.rs`의 `ICONS`)에 있을 때만 | `data/assets/icons/<종류>/<값>.webp`·`.png` → 엔진 폴더 `image/icon/<파일>`(확인된 종류만) |

- 넘기는 이름·id·종류는 **경로가 아니라 열쇠**다. 화면이 넘긴 문자열로 임의의 파일을 읽을 수 없다(경로 탈출 테스트:
  `assets.rs`의 `names_outside_the_catalog_never_reach_the_file_system` 등).
- 파일 이름 규칙은 엔진의 `scraper/cdn_fetch.py`의 `safe_filename()` 그대로다: `\ / : * ? " < > |` → `_`
  (예: `D : 킬러 와이프` → `D _ 킬러 와이프.webp`). Rust와 받기 스크립트가 같은 규칙을 쓰고, 테스트가 엔진 코드와 대조한다.
- **없는 이미지는 오류가 아니다** — `found: false`로 오고 부품이 대체 그림을 그린다.
  초상화 → 이름 첫 글자 / 보스 → 보스의 속성 색 바탕 / 아이콘 → 직접 그린 도형·글자.
- 읽은 내용이 WebP·PNG가 아니거나 2MB를 넘으면 넘기지 않는다.

`data/assets/`의 자리(받기 스크립트가 쓰는 곳이고, 사람이 직접 넣어도 된다):

```
data/assets/
  manifest.json                 받을 목록(받기 스크립트가 쓴다)
  portraits/<니케 이름>.webp      엔진 폴더에 없는 초상화만
  bosses/<보스 id>.webp|.png
  icons/element/{fire,water,wind,electric,iron}.webp|.png
  icons/burst/{1,2,3,all}.webp|.png
  icons/class/{attacker,supporter,defender}.webp|.png
  icons/corp/{elysion,missilis,tetra,pilgrim,abnormal}.webp|.png
  icons/weapon/{ar,smg,sg,sr,mg,rl}.webp|.png
```

**게임 이미지를 저장소에 넣지 않는다.** 게임 이미지는 SHIFT UP / Level Infinite의 권리물이다(`docs/spec.md` §7) —
`data/assets/`·`data/captures/`는 gitignore이고, 초상화는 엔진 서브모듈(남의 저장소)에 있는 것을 읽을 뿐이다.
테스트는 코드로 만든 가짜 이미지(머리 바이트만 맞는 몇십 바이트)로만 한다.

## 8. 리소스 — 어디서 받는가

허용되는 출처는 둘뿐이다:

- (가) **게임사가 웹에 공개하는 공식 도구 사이트의 CDN** — 엔진이 초상화를 받는 곳과 같다(`https://sg-tools-cdn.blablalink.com`).
- (나) **사용자가 찍은 캡처**(`data/captures/`).

하지 않는 것: **설치된 게임 클라이언트의 파일을 풀거나 복호화하지 않는다**(보호 장치를 넘는 일이다). 다른 팬 사이트의 이미지를
가져오지 않는다. 주소를 추측해 여러 번 두드려 보지 않는다.

### 무엇을 찾았고 무엇을 못 찾았나

엔진 스크레이퍼의 코드·주석(`vendor/nikke-calc/scraper/cdn_fetch.py`·`cdn_path.py`·`cdn_tables.py`)과 받아 둔 표를 읽은 결과다.

| 종류 | CDN 경로 | 지금 쓰는 것 |
|---|---|---|
| 니케 초상화 | **확인됨** — `cdn_fetch.py`의 `PORTRAIT_PATH`(`/character/mi/mi_c{번호:03d}_00_s.webp`, 256×512) | 엔진 폴더의 `image/`(서브모듈에 이미 213장). 엔진 폴더에 없는 니케만 받는다 |
| 속성 아이콘 5종 | 못 찾음 | 엔진 폴더의 `image/icon/icn_element_*.webp`(파일 이름은 `runner/squads.py`의 `ELEMENT_ICON`에서 확인) → 없으면 직접 그린 도형 |
| 버스트 단계 아이콘 4종 | 못 찾음 | 엔진 폴더의 `image/icon/icn_burst_*.webp`(`BURST_ICON`) → 없으면 직접 그린 배지 |
| 클래스 아이콘 3종 | 못 찾음 | 엔진 폴더의 `image/icon/icn_class_*.webp`(`CLASS_ICON`) → 없으면 글자 배지 |
| 기업 아이콘 5종 | 못 찾음 | **직접 그린 글자 배지.** 엔진 폴더에 `icn_corp_01~05.webp`가 있지만 어느 번호가 어느 기업인지 코드에서 확인하지 못해 쓰지 않는다 |
| 무기 종류 아이콘 6종 | 못 찾음(엔진 폴더에도 없다) | **직접 그린 글자 배지**(AR·SMG·SG·SR·MG·RL) |
| 이상 개체 보스 이미지 5종 | 못 찾음(엔진은 이상 개체 보스를 다루지 않는다) | 사용자의 캡처에서 잘라 둔 `data/captures/bosses/<id>.png`(192×192) → 없으면 속성 색 대체 |
| 장비 부위 아이콘 | 못 찾음(장비 **표**의 경로만 있다) | 아직 쓰는 화면이 없다 |

그래서 **지금 받을 것은 0개다**(초상화 206장은 엔진 폴더에 이미 있다). 엔진 데이터에 새 니케가 생겼는데 초상화가 엔진 폴더에
없을 때만 받을 것이 생긴다. 아이콘의 CDN 경로를 알게 되면 `scripts/fetch-assets-lib.mjs`의 목록 만들기에 더하고
`UNRESOLVED`에서 뺀다 — 근거(엔진 코드의 어디에 그 경로가 있는지)를 `evidence`에 적는다.

엔진 폴더의 아이콘(`image/icon/`)을 읽는 것은 수락 조건의 「`data/assets/`에 있으면 그것, 없으면 직접 그린 것」 사이에 한 단계를
더한 것이다: 받아 둔 것 → **엔진 폴더의 것** → 직접 그린 것. 사용자의 요청("아이콘은 직접 그리기보다 게임의 것을")에 맞추려고 넣었고,
초상화와 같은 폴더(엔진 서브모듈)라 새 출처가 아니다. 세 단계 모두 테스트한다.

### 받기 스크립트

```bash
node scripts/fetch-assets.mjs --list       # 받을 것의 종류별 개수·출처·어림 크기 (네트워크를 쓰지 않는다)
node scripts/fetch-assets.mjs --manifest   # 받을 목록을 data/assets/manifest.json에 쓴다 (네트워크를 쓰지 않는다)
node scripts/fetch-assets.mjs --run        # 실제로 받는다 — 사람이 실행한다. 먼저 --list로 확인할 것
```

- **실제로 받는 것은 `--run`뿐이다.** 에이전트는 `--run`을 돌리지 않는다.
- 받는 호스트는 공식 CDN 한 곳으로 고정이다 — 바꾸는 인자·환경 변수가 없다. 다른 호스트의 주소, `data/assets/` 밖으로 나가는
  저장 위치는 거부한다. 다른 주소로 넘기는 응답(리다이렉트)은 따라가지 않는다.
- 한 번에 조금씩: 동시에 2개, 요청 사이 300ms. 이미 있는 파일은 건너뛴다. 실패는 목록으로 보고한다.
  연달아 5건 실패하면 멈춘다(주소 규칙이 바뀌었거나 서버가 막았다 — 계속 두드리지 않는다).
- 받은 내용이 그 형식의 이미지가 아니면(오류 페이지 등) 저장하지 않는다. 파일 하나 2MB까지.

`data/assets/manifest.json`의 모양:

```jsonc
{
  "schema_version": 1,
  "kind": "asset_manifest",
  "generated_at": "2026-11-12T10:00:00.000Z",
  "host": "https://sg-tools-cdn.blablalink.com",
  "host_note": "게임사가 웹에 공개하는 공식 도구 사이트의 CDN — …",
  "dest_root": "data/assets",
  "limits": { "concurrency": 2, "delay_ms": 300, "max_file_bytes": 2097152 },
  "entries": [
    {
      "kind": "portrait",                       // 종류
      "name": "니케 이름",                        // 이름

      "evidence": "vendor/nikke-calc/scraper/cdn_fetch.py — PORTRAIT_PATH와 download_images()… 주소 규칙은 scraper/cdn_path.py — obfuscate()"   // 근거가 된 엔진 코드 위치
```

함수가 낸 값과 대조하고, 상수(호스트·소수 목록·초상화 경로)를 엔진 코드와 대조한다. 엔진 서브모듈을 올릴 때 이 테스트가 깨지면
규칙이 바뀐 것이다.

## 9. 한 줄 요약

`src/core/summary.mjs`의 `summarizeInterceptBoss(boss, options)` — 순수 함수(웹뷰와 Node가 함께 쓴다).
요격전 추천 결과의 보스 하나에서 일반 사용자가 읽을 한 문장을 만든다.

**결과에 있는 것만 말한다.** 재료는 네 가지뿐이다: 1위 편성의 멤버별 딜 비중, 약점 속성과 그 속성인 보유 니케(`weak_pool.owned`),
속성 상성을 반영했는가(`element.reflected`), 자리 순서를 바꿔 얻은 차이(`placement`).

문장은 최대 세 토막이다(있는 것만, 이 순서로 — 첫 토막 뒤는 ` — `, 그 뒤는 `, `로 잇고 마침표 하나로 끝낸다):

| 토막 | 조건 | 문장 |
|---|---|---|
| ① 속성 | 속성 상성을 반영하지 못했다 | `속성 상성 미반영` |
| | 가장 딜이 큰 니케가 약점 속성이고, 약점 속성 니케의 합이 50% 이상 | `약점 속성(작열) 딜러 중심` |
| | 약점 속성 니케의 합이 50% 이상 | `약점 속성(작열) 니케가 딜의 55%` |
| | 약점 속성 니케가 있지만 50% 미만 | `약점 속성(작열) 니케의 딜은 12%뿐` |
| | 편성에 약점 속성 니케가 없다 | `약점 속성(작열) 니케 없는 편성` |
| | 누가 약점 속성인지 모른다 | (말하지 않는다) |
| ② 딜 구성 | 한 명이 50% 이상 | `○○ 혼자 딜의 62%` |
| | 그렇지 않다 | `○○ 30% · △△ 28%로 딜이 나뉜다` |
| | 비중이 결과에 없다 | (말하지 않는다) |
| ③ 자리 순서 | 순서를 바꿨고 딜이 5% 이상 늘었다 | `자리 순서를 바꿔 딜 +8%` |

예: `약점 속성(작열) 딜러 중심 — 라피 : 레드 후드 혼자 딜의 62%, 자리 순서를 바꿔 딜 +8%.`

기준값(50%·5%)은 어림이다 — 「절반 이상」「크게」를 숫자로 옮긴 것이고 근거가 있는 값이 아니다.
말할 것이 하나도 없으면 `1위 편성의 딜 구성은 결과에 없다.`, 계산하지 않은 보스는 `아직 계산하지 않은 보스다.`
`facts`(문장을 만든 재료)도 함께 돌려준다 — 화면이 타일의 강조에 같은 판단을 쓴다.

보스 패턴·실전 기록처럼 결과에 없는 것은 문장에 넣지 않는다. 「추정」이라는 사실은 문장이 아니라 **항상 보이는 배지**가 알린다.

## 10. 남은 시간 어림

`src/core/eta.mjs`의 `estimateRemaining({done, total, elapsedMs})` — 순수 함수(시계를 읽지 않는다).

- 끝난 건수가 3건 미만이면 숫자를 내지 않고 **「계산 중」**만 말한다(전체 건수·경과 시간을 모를 때도).
- 그 뒤에는 `경과 ÷ 끝난 건수 × 남은 건수`. 어림할 수 없으면 `remaining_ms`는 `null`이다(0이 아니다).
- 말: 5초 미만 「곧 끝남」 · 1분 미만 5초 단위 올림(「약 45초 남음」) · 10분 미만 30초 단위(「약 3분 30초 남음」) ·
  1시간 미만 분 단위 · 그 위는 「약 1시간 15분 남음」 · 끝나면 「끝남」.

가정은 「지금까지의 평균 속도가 끝까지 간다」 하나뿐이다. 편성마다 계산 시간이 다르고 캐시에 있던 것은 곧바로 끝나므로
크게 틀릴 수 있다 — 그래서 「약」을 붙이고 자잘한 단위를 버린다.

## 12. 부품 모아 보기

모든 부품과 상태(이미지 있음/없음, 긴 이름, 계산 중, 빈 상태, 오류)를 한 화면에서 본다. **개발 실행에서만** 뜬다 —
빌드한 앱에는 그 화면의 코드가 들어가지도 않는다(`main.ts`의 `import.meta.env.DEV` 갈래).

```powershell
# 앱 창에서(실제 초상화·보스 이미지가 보인다):
$env:VITE_UI_GALLERY = '1'; npm --prefix app run tauri dev
# 브라우저에서(이미지 명령을 부를 수 없어 전부 대체 그림으로 보인다 — 모양·배치만 볼 때):
npm --prefix app run dev      # 그리고 주소 뒤에 ?gallery 를 붙여 연다
```

여기의 숫자는 지어낸 보기 값이다(`app/src/ui/gallery/samples.ts`) — 화면 맨 위에 「검증용 데이터」 배지로 밝힌다.
