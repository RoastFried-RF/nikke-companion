# 니케 컴패니언 — 요구사항

출처: 2026-11-12 ChatGPT 대화 "니케 오버레이 앱 조사" 전문과 사용자의 시작 지시.
이 문서가 이후 작업의 기준이다. 대화 전문을 다시 읽을 필요는 없다.

분류 표기: **[확정]** 사용자가 직접 요구 · **[제안]** 이전 답변의 기술 제안(강제 아님) ·
**[가정]** 재검증이 필요한 사실 · **[추정]** 일정·난도 추정.

## 1. 전체 목표 [확정]

개인용 Windows 데스크톱 앱. 승리의 여신: 니케 한국어 PC판 위에서 동작한다.

| ID | 요구사항 | 단계 |
|---|---|---|
| R1 | 니케 PC판 위의 데스크톱 오버레이 | 2 |
| R2 | 보유 니케·장비·스킬·투자 상태 관리(수동 등록)와 가져오기(자동 등록) | 1(수동) / 2(가져오기) |
| R3 | 계정과 콘텐츠 조건에 맞춘 편성 추천 | 1 |
| R4 | 성장 목표·투자 효율 추천(재화 제약 포함) | 2 |
| R5 | 신규 캐릭터·변경 데이터 기반 자체 티어 자동 갱신(AI API + 계산 엔진) | 3 |
| R6 | 레이드 화면 감지와 상황별 추천 | 4 |
| R7 | 주간 티어·메타 조사 | 4 |
| R8 | 로스트 섹터 공략 안내 오버레이 | 5 |
| R9 | 검증된 범위의 로스트 섹터 자동 조작·클리어 | 6 |

후속 단계 기능은 MVP에서 빠질 수 있지만 요구사항에서 삭제하지 않는다.
구현되지 않은 것을 완료로 표시하지 않는다.

## 2. 실행 조건 [확정]

- 개발·코드 검토는 Fable 5.2(`claude-fable-5-2`)만 쓴다. Claude·Codex 병행안은 폐기.
- Effort 기본 `high`. 계산식·버스트 타임라인·복잡한 상태 전이 분석에만 `xhigh`.
- 동시에 코드를 바꾸는 작성자는 1개.
- 최소 하네스(실행·검증·재개)를 먼저 갖춘 뒤 제품 개발을 잇는다.
- Fable 5.2를 쓸 수 없으면 기록하고 멈춘다. 다른 모델로 조용히 바꾸지 않는다.
- 작업 폴더: `E:\code\nikke-companion` (사용자가 "E:\ 아무 데나"로 지정, 2026-11-12).

## 3. 단계별 범위

### 단계 1 — 계산 경로 (현재)
`계정 상태 → 전투 조건 → 계산 엔진 → 편성 비교 → 결과 표시` 한 경로를 실제 엔진으로 연결한다.
- 계정 상태는 수동 입력 JSON. 검증용 데이터는 `is_test_data: true`로 표시한다.
- 후보 편성은 사용자가 주거나 간단한 생성 규칙으로 만든다. 전수 탐색은 단계 2.
- 결과는 CLI 표와 JSON. JSON이 이후 오버레이의 입력이 된다.

### 단계 2 — 개인용 MVP
- Tauri 창·오버레이(클릭 통과·게임 창 추적·캡처) — **실제 니케 위 검증 필요**.
- blablalink 계정 가져오기(엔진의 `scraper/profile_fetch.py` 경로 검토).
- 편성 탐색(후보 필터 → 유망 편성 → 정밀 시뮬), 성장 목표·투자 비교.

### 단계 3 — 자동 티어
- 신규 캐릭터·밸런스 변경 감지 → 스킬 구조화 → 엔진 지원 여부 판정 → 시뮬 → 티어.
- 미지원 효과는 **평가 보류**. 누락 효과를 0으로 두고 확정 티어를 내지 않는다.
- 일반 티어와 내 계정 육성 우선순위를 구분한다. 기존 편성도 재평가한다.
- 평가에는 데이터·엔진·시나리오·등급 규칙 버전, 출처, 평가 시각, 미확정 항목을 남긴다.
- 상태 표기: 예측 평가 / 실측 대조 완료(조건 범위 명시) / 평가 보류.

### 단계 4~6
화면 인식·레이드 추천·메타 조사 → 로스트 섹터 안내 → 제한된 맵의 자동 조작(행동 → 화면 변화 확인 → 복구/중단).

## 4. 원칙 [확정]

- 수치 계산과 제약 검증은 재현 가능한 계산 코드가 한다. AI는 해석·지휘·설명을 맡는다.
- "무조건 최적"이 아니라 "현재 데이터와 지원 조건에서 찾은 가장 좋은 후보"로 표시한다.
- 가져오지 못한 계정 항목은 `미확인`으로 두고 사용자가 고칠 수 있게 한다.
- 모의 데이터와 실제 계정 데이터를 구분한다. 개인 계정 데이터는 저장소에 올리지 않는다(`data/accounts/`).
- 실측하지 않은 결과를 실전 검증 완료로 표시하지 않는다.
- 배포·공개 게시·실제 게임 계정에 영향을 주는 조작은 그 단계에서 사용자 확인을 받는다.
- 자동 입력(R9)은 계정 제재 위험이 있다. 구현 전 사용자에게 위험을 다시 알리고 확인받는다.

### 게임과의 상호작용 규칙

- **앱 코드(캡처·창 추적)는 게임을 읽기만 한다.** 게임 창을 옮기거나 앞으로 가져오지 않고, 입력을 보내지 않고,
  게임 프로세스 메모리를 읽거나 무엇을 주입하지 않는다. 표준 창·캡처 API만 쓴다.
- **안티치트 회피 기법은 만들지 않는다.** 입력을 사람처럼 위장하거나 탐지를 피하는 코드는 넣지 않는다.
- 캡처 이미지는 계정 정보와 게임 화면을 담는다. `data/captures/`(gitignore)에만 두고 커밋하지 않는다.
- 2026-11-12 사용자 결정: 화면 인식 개발용 캡처를 모으기 위해 대화형 세션의 Claude가 computer use로 게임 화면을
  이동한다. 범위는 **이동과 보기만** — 상점·모집·재화 소모·육성 확정·전투와 대전 입장은 누르지 않고, 결제나 유료 재화가
  걸린 화면은 건드리지 않으며, 예상 밖 화면(구매 팝업 등)에서는 멈춘다. 계정 제재 위험은 사용자에게 알렸다.
- 조작 자동화(R9)는 화면 인식이 생긴 뒤에 만든다: 행동 → 화면 변화 확인 → 실패 시 중단, 허용 동작 목록,
  비상 정지 단축키, 실행할 때마다 명시적으로 켜는 잠금.

## 6. 재검증할 가정

| 가정 | 상태 |
|---|---|
| RapiLab이 86명을 지원하고 빌드된다 | README 확인만. **빌드·실행 안 함** |
| nikke-calc가 Python 3.12에서 돈다 | 확인(샘플 시뮬·테스트 39건 통과, 2026-11-12) |
| nikke-calc 수치가 실전과 맞는다 | **미검증**. 엔진 문서도 "참고용"으로 밝힌다 |
| blablalink에서 계정을 가져올 수 있다 | 엔진에 수집기 존재. **실행 안 함**(로그인 세션 필요) |
| Tauri 오버레이(투명·항상 위·클릭 통과)가 니케 전체화면·창 모드에서 동작 | **미검증**(실제 게임 필요). 전체 화면 전용 모드에서는 가려질 수 있다 |
| 구독 API 크레딧·요금제 | 미확인. 이 프로젝트 판단에 쓰지 않는다 |
| 일정(MVP 6~12주) [추정] | 계획용. 근거 없음 |
| Claude Code 기본 Effort가 medium | 미확인. 하네스가 `--effort`를 항상 명시하므로 무관 |
