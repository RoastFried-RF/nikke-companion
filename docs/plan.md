## 0. 먼저 — 사람이 봐야 하는 것

P-026~P-034와 P-014의 화면은 **자동 검증만 통과했고 아무도 눈으로 보지 않았다.** 다음 작업의 대부분은 여기서
나오는 결함일 것이다. 순서대로:

1. **앱을 띄운다** — `npm --prefix app run tauri dev`. 앱 창의 메뉴 여섯(홈 · 요격전 · 내 니케 · 편성 도구 · 티어 · 설정)과
   오버레이 위젯(접힘 · 한 줄 카드 · 펼침, `Alt+Shift+M`)이 뜨고 읽을 만한지 본다.
2. **계정을 받는다** — 설정 > 계정 연결. 기본 경로는 크롬 확장이다: `chrome://extensions` → 개발자 모드 →
   「압축해제된 확장 프로그램을 로드합니다」로 저장소의 `extension/` 폴더를 고르고, 앱에서 「크롬 확장 연결」을 켠 뒤
   화면의 연결 코드를 확장에 적는다. (에이전트는 이 단계를 하지 않는다 — 사람이 한다.)
3. **요격전 추천을 계산한다** — 요격전 화면에서 보스 5종. 추천 편성이 납득이 가는지 본다.
4. **게임 위에서 본다** — 니케를 띄우고 이상 개체 요격전 화면에서: 오버레이가 게임 위에 머무는지, 설정 > 오버레이의
   자동 추적을 켰을 때 보고 있는 보스를 맞게 따라가는지(`nikke-capture --recognize-live`로도 확인할 수 있다),
   화면을 떠나면 위젯이 접히는지.
5. **추정치를 실제와 견준다** — 추천 1위 편성으로 모의전을 돌고 대미지를 요격전 화면의 「내 기록」에 적는다. 배지가
   「추정 · 기록과 ○○% 차이」로 바뀐다. 이 차이가 아래 2번(보스 값 보정)의 근거다.
6. 그 밖의 확인 항목은 `node scripts/verify.mjs --status`의 「실제 환경 검증 대기」와 작업별 `manual_checks`에 있다.

결함이 나오면: 무엇을 했을 때 무엇이 보였는지(가능하면 화면 캡처) 적어 세션에 주면, 세션이 `tasks.json`에 작업으로
정의하고 고친다.

## 2. 추천 품질 — 보스 값 보정

지금 요격전 추천은 보스마다 **속성 상성만** 다르다. 방어력 · 코어 · 파츠 · 거리 · 전투 시간 · 패턴은 모른다
(`docs/intercept.md` §모르는 것 — 미확인으로 표시하고 0으로 두지 않는다).

- 0-5의 기록이 쌓이면 추정과 기록의 비율을 보스별로 본다. 비율이 편성과 무관하게 일정하면 보스 값(방어력 · 전투
  시간) 쪽이고, 편성마다 다르면 엔진이 계산하지 않는 효과 쪽이다. **추정치를 기록에 맞춰 덮어쓰지 않는다** — 보정은
  보스 값의 가설을 세우고, 출처(게임 화면 · 기록)를 적은 뒤에 한다.
- 게임 화면에서 확인할 수 있는 값(전투 시간 제한, 파츠 유무)은 캡처로 확인해 `data/intercept/anomaly.json`에 넣는다.
- 후보 풀이 좁다: 실제 계정에서 약점 속성 보유 니케의 대부분이 풀 밖이었다. 풀 크기 · 예산 조정, 큐브 · 운용 반영.

## 작업으로 만드는 법

1. `docs/spec.md`와 `.harness/progress.md`를 읽는다(`CLAUDE.md` §읽는 순서).
2. `.harness/tasks.json`에 작업을 더한다 — `id`, `title`, `description`, `deps`, `acceptance`(검증할 수 있는 문장),
   `verify`(명령 목록), `manual_checks`, `protected`, `status: "pending"`, `attempts: 0`. 기존 작업(P-029 등)을 본으로 삼는다.
   실제 게임이 있어야 하는 검증 명령에는 `requires_cmd`를 붙인다(P-011).
3. `node scripts/autopilot.mjs --max-iterations 3 --max-minutes 300`으로 돌리거나 대화형으로 한 작업씩 한다. 완료는
   `node scripts/verify.mjs <작업ID>`(대화형으로 완료 처리까지 하려면 `--record`)가 통과해야 한다.
4. 끝나면 `node scripts/verify.mjs --all`로 전체를 다시 보고 `.harness/progress.md`를 갱신한다.

비용의 어림: 지금까지 작업 하나에 10~50분, CLI 보고 기준 $7~$38, 주간 Fable 한도의 3~4%p였다
(`.harness/progress.md` §자율 실행 기록). 모델은 Fable 5.2만 쓴다 — 한도에 걸리면 하네스가 모델을 바꾸지 않고 멈춘다.
