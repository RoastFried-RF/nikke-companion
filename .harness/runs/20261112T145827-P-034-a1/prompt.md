작업 ID: P-034
제목: 계산기: 소장품 강화 등 — 값이 확인되는 것만
설명: 먼저 docs/ui-redesign.md(개편의 구조·원칙·부품)를 읽어라. 이 작업은 커뮤니티 도구 모음(니케 마이너 갤러리 "니케 유용한 툴 모음집")의 도구들을 대화형 세션이 직접 열어 보고 고른 기능이다 — 그 사이트들의 코드·이미지·데이터는 가져오지 않고 기능의 아이디어만 참고한다. 계산은 src/core의 순수 모듈(node: import 금지)로 만들고 엔진(vendor/nikke-calc)은 고치지 않는다. 엔진이 지원하지 않는 것은 지원하는 것처럼 계산하지 말고 "지원하지 않음"으로 화면과 결과에 적는다. 화면은 P-026의 부품으로 그리고 데스크톱 앱 창(P-027)에 넣는다. 화면의 글은 일반 사용자가 읽는 한국어다. 시험 데이터는 data/samples/만 쓴다(실제 계정 파일을 읽지 않는다). 참고한 것: 소장품 강화 최적화 시뮬레이터(관리 키트 세 종류의 경험치와 보유 비율로 강화 구간의 최소 사용 조합을 찾는다), 니붕 시뮬레이터(모집 시뮬). **이 작업은 값의 출처가 있어야 한다.** 필요한 표(소장품 단계별 필요 경험치, 키트별 경험치, 모집 확률)가 엔진의 데이터(vendor/nikke-calc/data/ — base_stat_tables 등)나 엔진 스크레이퍼가 받는 공식 표에 있는지 먼저 확인하라. **확인된 값만 쓴다 — 기억이나 다른 사이트의 숫자를 옮기지 마라.**

수락 조건:
- 조사 결과를 docs/calculators.md에 적는다: 어떤 표가 어디(파일·키)에 있고 무엇이 없는지. 값이 없는 계산기는 만들지 않고 "출처 없음"으로 적는다 — 이 경우에도 작업은 완료다(만든 것이 없으면 화면도 더하지 않는다)
- 값이 확인된 계산기만 만든다. 소장품 강화: 지금 단계·목표 단계·가진 키트 수를 넣으면 필요한 경험치와 키트 조합(가진 것 안에서 남기는 양이 가장 적은 조합)을 보인다 — 조합 찾기는 순수 함수로 두고 작은 사례에서 전수 탐색과 같은 답임을 테스트한다
- 모집 확률 계산은 공식 확률 표가 데이터에 있을 때만 만든다(없으면 만들지 않는다)
- 만든 계산기는 편성 도구 화면의 "계산기" 구획에 넣고, 쓰는 값의 출처를 화면 아래에 적는다
- 단위 테스트(순수 함수)와 화면 테스트(가짜 backend)가 있고, 실제 엔진을 쓰는 통합 테스트가 한 건 이상 있다(3분 안쪽). 기존 테스트가 계속 통과하고 cargo clippy --all-targets에 경고가 없다. docs/data-model.md·docs/ui-redesign.md·app/README.md·루트 CLAUDE.md를 갱신한다
