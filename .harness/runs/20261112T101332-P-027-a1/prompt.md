작업 ID: P-027
제목: UI 개편 2: 데스크톱 앱 창 — 왼쪽 메뉴, 홈·요격전·내 니케·편성 도구·티어·설정
설명: 먼저 docs/ui-redesign.md(P-026)를 읽어라 — 개편의 배경·구조·원칙·토큰·부품이 있다. **이 작업**은 데스크톱 앱 창을 만든다: 앱을 실행하면 뜨는 일반 창(테두리·제목 표시줄 있음, 작업 표시줄에 보임, 크기 조절 가능, 기본 1100×720 안팎)이고, 지금 오버레이 창 안에 있는 기능(추천·비교, 요격전, 성장, 티어, 계정 받기 — 크롬 확장·붙여넣기·로그인 창)을 전부 이 창으로 옮긴다. 기능을 빼지 않는다. 오버레이 창(main)은 이 작업에서는 지금 화면 그대로 두어도 되지만(P-028이 위젯으로 바꾼다), 두 창이 같은 결과를 보게 만드는 바탕(마지막 요격전 결과와 기본 계정을 디스크에 두고 두 창이 읽는다)은 여기서 만든다. 계산 로직을 화면에 다시 쓰지 않는다 — src/core·src/tier 함수를 그대로 부른다.

수락 조건:
- 앱 창: 새 창이 capability에 따로 등록되고 필요한 명령만 갖는다(오버레이 창의 권한과 나눈다 — 오버레이는 결과 읽기·창 조작에 필요한 것만). 로그인 창(login)은 여전히 권한이 없다. 앱을 실행하면 앱 창이 뜨고, 오버레이는 설정에 따라 함께 뜨거나 게임을 찾았을 때 뜬다. 앱 창을 닫으면 어떻게 되는지(끝내기 또는 트레이 없이 오버레이만 남기기)를 정하고 문서에 적는다 — 프로세스가 남는 일이 없어야 한다(P-024)
- 왼쪽 메뉴와 화면: 홈, 요격전, 내 니케, 편성 도구(추천·비교·성장), 티어, 설정. 메뉴는 아이콘 + 짧은 이름이고 지금 화면과 계산 중인 화면이 표시된다. 마지막으로 본 화면을 기억한다
- 홈: 지금 상태를 체크리스트로 보인다(계정 연결·게임 창·오버레이·자동 추적)와 다음에 할 일 단추 하나. 처음 실행이면 세 단계 안내(계정 연결 → 게임 켜기 → 요격전 화면 열기)
- 요격전: 위에 보스 5종 카드(이미지·이름·약점·1위 총딜), 고른 보스의 추천 1위(한 줄 요약, 큰 총딜 숫자와 "추정" 배지, 니케 타일 5개 — 자리 순서대로, 약점 속성 강조, 딜 비중 막대), 2·3위 줄(누르면 그 편성의 타일로 바뀐다), "약점 속성인데 후보에 못 든 니케" 요약, 접힌 "계산 조건"(미확인 값·가정·주의 — 내용은 빠짐없이). 다시 계산은 단추 하나 + 정밀도 셋 중 고르기(빠르게·보통·꼼꼼히 — 시뮬 예산의 일반 사용자용 이름. 각각 대략 몇 분인지 보인다). 계산 중에는 진행 패널(어느 보스·진행·남은 시간 어림·중단)이 보이고 이전 결과는 그대로 남는다
- 파일 경로 입력을 없앤다: 계정은 기본 계정 하나를 기억해 자동으로 쓰고(설정에서 바꾼다), 보스 값은 내장된 data/intercept/anomaly.json을 쓴다. 파일을 직접 고르는 길은 설정의 "고급"에만 남긴다. 계정이 없으면 계산 단추 대신 "계정 연결" 안내가 보인다
- 내 니케: 보유 니케를 초상화 격자로 보인다(이름·속성·버스트, 육성 요약 — 돌파·스킬·오버로드 줄 수를 작은 표시로). 속성·버스트·"육성한 것만" 거르기와 이름 찾기. 계정 요약(니케 수, 동기화 레벨, 마지막으로 받은 때)과 "계정 새로 받기"로 가는 단추
- 편성 도구·티어: 기존 추천·비교·성장·티어 화면을 새 부품으로 옮긴다(니케 타일·딜 막대·등급 배지). 티어는 등급별 초상화 묶음으로 보이고 평가 보류·미지원 효과·임시 규칙 표시는 유지한다
- 설정: 계정 연결(크롬 확장 — 권장, 붙여넣기, 로그인 창), 오버레이(함께 띄우기·자동 추적·자동 이동·붙이기·단축키 안내), 엔진 정보(버전·폴더 문제), 고급(파일 직접 고르기)
- 두 창이 같은 것을 본다: 마지막 요격전 결과와 기본 계정 이름을 디스크(계정 폴더 — gitignore)에 저장하고, 앱 창이 계산을 끝내면 오버레이 창이 새 결과를 받는다(이벤트 또는 다시 읽기). 앱을 다시 켜도 마지막 결과가 보인다. 형식 검사 실패(다른 종류·다른 판)는 한국어로 알리고 이전 것을 둔다
- 문구: 화면의 글은 일반 사용자가 읽는 한국어다 — 파일·JSON·시뮬·예산 같은 말을 쓰지 않는다(고급 설정 제외). 오류는 무슨 일이 있었고 무엇을 하면 되는지 한 문장씩. 원칙상 숨기면 안 되는 표시(추정·미확인 값·미지원 효과·검증용 데이터)는 배지로 남아 있다 — 테스트로 확인한다
- 각 화면의 컴포넌트 테스트(가짜 backend)와 화면 사이 흐름 테스트(계정 없음 → 연결 → 계산 → 결과 → 다시 켜도 복원). 기존 테스트 가운데 옛 화면 구조에 묶인 것은 새 구조에 맞게 옮기되, 확인하던 내용(동작)은 그대로 확인한다 — 무엇을 왜 옮겼는지 progress.md에 적는다. cargo clippy --all-targets 경고 없음. app/README.md·docs/ui-redesign.md·루트 CLAUDE.md 갱신
