제목: UI 개편 1: 디자인 기반 — 어두운 테마, 초상화·보스 이미지, 공통 부품
설명: **개편의 배경(세 작업 공통 — docs/ui-redesign.md에 적고 이후 작업이 그 문서를 따른다)**: 사용자가 실제로 써 보고 "일반 사용자는 보고 알 수가 없다, 시각화 중심으로 전부 바꿔야 한다, 캐릭터 이미지와 보스 이미지를 쓰고 더 트렌디하고 컴팩트하게, Blitz(https://blitz.gg/lol/overlays)와 OP.GG 데스크톱(https://op.gg/desktop/ko/games/lol)을 참고해 **데스크톱 앱을 만들고 오버레이를 붙이는 구조**로"라고 했고, 2026-11-12 대화에서 시안을 확인했다. 확인된 구조: (1) **데스크톱 앱** — 일반 창, 어두운 배경, 왼쪽 아이콘 메뉴(홈·요격전·내 니케·편성 도구·티어·설정). 계정 연결·계산 실행·설정은 전부 여기서 한다. (2) **오버레이** — 게임 위에 뜨는 작은 위젯. 결과만 보여 준다: 보스 이미지·이름·약점·총딜·초상화 5장 한 줄, 접으면 보스 이름과 총딜만. 두 참고 사이트에서 본 것: 본체는 일반 창의 데스크톱 앱(초상화가 든 촘촘한 목록, 색 배지와 막대, 보라 계열 강조색, 왼쪽 아이콘 메뉴)이고 오버레이는 한 가지 일만 하는 작은 조각이다. 시안의 요격전 화면: 위에 보스 5종 카드(이미지·이름·"약점 ○○ · 총딜"), 아래에 고른 보스의 추천 1위 — 큰 총딜 숫자 하나와 "추정" 배지, 세로로 긴 초상화 타일 5개(왼쪽 위 버스트 단계 배지 I/II/III, 오른쪽 위 속성 점, 보스의 약점 속성 니케는 속성 색 테두리, 이름, 딜 비중 막대와 %), 2·3위는 한 줄 요약. 원칙: 파일 경로 입력 칸을 없앤다(계정은 한 번 연결하면 기억, 보스 값은 내장) · 숫자 표 대신 타일·막대·배지 · 맨 위에 한 줄 요약 문장 · 경고와 계산 조건은 접어 두되 "추정·실전 미대조"는 항상 보인다 · 정보 영역은 불투명 카드 · 한국어 문구는 게임 용어만 쓰고 개발 용어(파일·JSON·시뮬·예산)는 쓰지 않는다. 숨기면 안 되는 것(프로젝트 원칙): 미확인 값·미지원 효과·검증용 데이터 표시 — 눈에 띄는 배지로 줄이되 없애지 않는다. **이 작업**은 기반만 만든다: 디자인 토큰, 이미지 불러오기, 공통 부품, 한 줄 요약. 기존 화면은 그대로 두고 동작해야 한다(화면을 새 구조로 옮기는 것은 P-027·P-028). 이미지: 캐릭터 초상화는 엔진 폴더의 image/<이름>.webp(256×512, 213장 — 파일 이름 규칙은 vendor/nikke-calc/scraper/cdn_fetch.py의 safe_filename을 읽어 그대로 따른다. 추측하지 마라)에서 읽는다. 보스 이미지는 data/captures/bosses/<보스 id>.png(192×192, 사용자의 캡처에서 잘라 둔 것 — gitignore. id는 data/intercept/anomaly.json의 id)에서 읽는다. **게임 이미지를 저장소에 넣지 마라**(테스트는 코드로 만든 가짜 이미지로). 네트워크 권한을 더하지 않는다 — 이미지는 Rust 명령이 로컬 파일을 읽어 넘긴다. **리소스 받기(2026-11-12 사용자 요청: "리소스는 게임 리소스에서 뽑아서 쓰라")**: 아이콘과 이미지는 직접 그리기보다 게임의 것을 쓴다. 허용되는 출처는 둘이다 — (가) 게임사가 웹에 공개하는 공식 도구 사이트의 CDN(엔진이 초상화를 받는 곳과 같다: vendor/nikke-calc/scraper/cdn_fetch.py·cdn_path.py·cdn_tables.py에 경로 규칙과 표가 있다), (나) 사용자가 찍은 캡처(data/captures/). **설치된 게임 클라이언트의 파일을 풀거나 복호화하지 마라**(보호 장치를 넘는 일이고 이 프로젝트의 원칙에 어긋난다). 다른 팬 사이트의 이미지를 가져오지도 마라. 받을 대상: 속성 아이콘 5종, 버스트 단계·무기 종류·클래스·기업 아이콘, 이상 개체 보스 이미지, (있으면) 장비 부위 아이콘. 어떤 경로에 무엇이 있는지는 엔진 스크레이퍼의 코드·주석과 받아 둔 표에서 **확인된 것만** 쓴다 — 주소를 추측해 여러 번 두드려 보지 마라. 확인하지 못한 종류는 받지 않고 직접 그린 단순한 도형 아이콘으로 대신하며, 무엇을 못 찾았는지 docs/ui-redesign.md에 적는다. 받은 파일은 data/assets/(gitignore에 더한다)에 두고 저장소에 넣지 않는다. **이 작업에서 실제로 내려받지는 마라** — 받는 스크립트와 목록만 만들고, 실행은 사람이 한다(받기 전에 출처·개수·크기를 보여 준다).

수락 조건:
- docs/ui-redesign.md: 개편의 배경·구조·원칙(위 설명), 화면 목록, 디자인 토큰 표, 부품 목록을 적는다. P-027·P-028이 이 문서를 따른다
- 디자인 토큰(app/src/styles): 어두운 테마의 배경·표면·글자·테두리 색, 강조색(보라 계열) 하나, 속성 색 다섯(작열·풍압·철갑·전격·수냉 — 게임의 보스 테마 색과 맞춘다: 풍압 초록·전격 보라·작열 빨강·철갑 주황·수냉 파랑), 상태 색(추정·미확인·오류), 간격·모서리·글자 크기 단계. 색을 코드 곳곳에 직접 적지 않는다 — 부품은 토큰만 쓴다
- 이미지 명령(Rust): 니케 초상화는 엔진 카탈로그에 있는 이름일 때만 엔진 폴더의 image/에서 읽는다(화면이 넘긴 문자열로 임의 경로를 읽을 수 없다 — 경로 탈출 테스트). 보스 이미지는 보스 묶음에 있는 id일 때만 읽는다. 없는 이미지는 오류가 아니라 "없음"으로 돌려준다. capability에는 새 명령만 더하고 파일·네트워크 플러그인은 더하지 않는다
- 니케 정보: 이름으로 속성·버스트 단계·무기·기업을 화면에서 얻을 수 있다(엔진 카탈로그에서 — 이미 있는 함수가 있으면 그것을 쓴다). 카탈로그에 없는 값은 "모름"이다
- 공통 부품(Vue, app/src/ui): 니케 타일(초상화 또는 이름 첫 글자 대체, 버스트 배지, 속성 점, 약점 속성 강조 테두리, 딜 비중 막대와 %, 긴 이름 말줄임 — 큰 것과 오버레이용 작은 것 두 크기), 보스 카드(이미지 또는 속성 색 대체, 이름, 약점 칩, 총딜), 속성 칩, 버스트 배지, 딜 막대, 순위 줄(2·3위), 상태 알약(연결됨·추정·미확인 등), 진행 패널(무엇을 하는 중인지·진행 막대·남은 시간 어림·중단), 뼈대 화면, 빈 상태(무엇을 하면 되는지와 단추 하나), 접는 "자세히" 구획. 부품마다 컴포넌트 테스트가 있다
- 부품 모아 보기 화면: 개발 실행에서 주소에 표시를 붙이면(?gallery 등) 모든 부품과 상태(이미지 있음/없음, 긴 이름, 계산 중, 빈 상태, 오류)를 한 화면에서 본다. 일반 실행에서는 보이지 않는다
- 한 줄 요약(순수 함수, src/core — node: import 금지): 요격전 추천 결과의 보스 하나에서 일반 사용자가 읽을 한 문장을 만든다(예: 약점 속성 딜러가 중심인지, 누가 딜의 절반 이상을 내는지, 자리 순서가 딜을 크게 바꿨는지). 결과에 없는 사실을 지어내지 않는다. 규칙과 문장을 단위 테스트한다
- 남은 시간 어림(순수 함수): 진행 건수와 경과 시간으로 남은 시간을 어림한다(처음 몇 건 전에는 "계산 중"만). 단위 테스트
- 기존 화면과 기존 테스트는 그대로 통과한다. cargo clippy --all-targets 경고 없음. app/README.md에 §디자인 기반(토큰·부품·이미지가 어디서 오는지·게임 이미지를 저장소에 넣지 않는 이유)을 더한다
- 리소스 받기 스크립트(scripts/fetch-assets.mjs): 받을 파일 목록(종류·이름·주소·저장 위치·근거가 된 엔진 코드 위치)을 data/assets/manifest.json 형식으로 만들고, `--list`는 받을 것의 종류별 개수만 보여 주며(네트워크 없음), `--run`만 실제로 받는다(이미 있는 파일은 건너뜀, 실패는 목록으로 보고, 한 번에 조금씩 — 서버에 부담을 주지 않게 동시 요청 수와 간격을 둔다). 받는 호스트는 공식 CDN 한 곳으로 고정하고 다른 호스트 주소는 거부한다. 테스트는 로컬 가짜 서버로 한다(실제 CDN을 부르지 않는다)
- 이미지 명령과 부품은 data/assets/의 아이콘이 있으면 그것을, 없으면 직접 그린 대체 아이콘을 쓴다(둘 다 테스트). 보스 이미지는 data/assets/에 있으면 그것을, 없으면 data/captures/bosses/의 캡처 조각을, 그것도 없으면 속성 색 대체를 쓴다
