작업 ID: P-022
제목: 오버레이에서 계정 받기: 로그인 창 또는 쿠키 붙여넣기 → 프로필 수집·변환·저장
설명: 지금은 사용자가 터미널에서 세 단계를 손으로 한다: (1) 브라우저에서 복사한 세션 쿠키를 vendor/nikke-calc/scraper/.session_cookie에 저장, (2) `python vendor/nikke-calc/scraper/profile_fetch.py`, (3) `node src/cli.mjs import-profile vendor/nikke-calc/profiles/me.json --name me`. 이것을 오버레이에서 한다: 쿠키를 붙여넣는 칸과 "계정 새로 받기" 단추 → Rust가 엔진의 수집 스크립트를 그대로 실행(엔진은 고치지 않는다. 절차와 경고의 뜻은 vendor/nikke-calc/.agent/skills/profile-sync/SKILL.md) → 받은 프로필을 src/core/import-profile.mjs의 변환 함수로 계정 상태로 바꿔(계산 로직을 화면에 다시 쓰지 않는다) data/accounts/<이름>.json에 저장 → 추천·요격전·성장 화면의 계정 경로를 그 파일로 맞춘다. **보안 규칙(어기면 실패다)**: 세션 쿠키는 계정 접근권이다. (a) 앱은 쿠키를 엔진의 scraper/.session_cookie 한 곳에만 쓴다. (b) 쿠키를 화면에 다시 보여 주지 않는다 — 입력 칸은 가려진 형식이고 저장하면 비운다. (c) 쿠키를 로그·오류 메시지·이벤트·명령 반환값·결과 문서·localStorage 어디에도 넣지 않는다. (d) 앱 자신은 쿠키를 네트워크로 보내지 않는다 — 보내는 것은 엔진 스크립트가 blablalink API에 하는 요청뿐이다. **너(에이전트)는 실제 vendor/nikke-calc/scraper/.session_cookie, vendor/nikke-calc/profiles/, data/accounts/의 파일을 읽지도 출력하지도 실행에 쓰지도 마라** — 개발과 테스트는 가짜 쿠키 문자열, 가짜 수집 스크립트, 샘플 프로필(data/samples/profile.sample.json)로만 한다. 실제 수집을 돌려 보지 마라(사용자 계정에 요청이 나간다). **쿠키를 받는 방법은 둘 다 만든다(2026-11-12 사용자 결정)**: (1) 오버레이가 여는 **로그인 창** — 별도 창에서 https://www.blablalink.com 을 열고, 사용자가 그 페이지에서 직접 로그인하면 Rust가 그 창의 쿠키 저장소에서 blablalink API 요청에 실릴 쿠키를 읽어 Cookie 헤더 한 줄로 만들어 scraper/.session_cookie에 저장한다. 앱은 아이디·비밀번호를 다루지 않는다(입력은 blablalink와 로그인 제공자의 페이지에서 이뤄진다). (2) **붙여넣기** — 로그인 창에서 로그인이 막히는 경우(예: 구글 계정 로그인은 앱 안의 창을 거부할 수 있다)를 위한 대안. Tauri에서 창의 쿠키를 읽는 API(예: 웹뷰의 cookies_for_url 계열)는 쓰는 판의 크레이트 소스·문서로 확인하고, 컴파일로 검증하라 — 기억으로 쓰지 마라. 필요한 API가 지금 판에 없으면 판을 올리는 대신 그 사실을 progress.md에 적고 붙여넣기만 완성하라. 로그인 창을 실제로 띄워 페이지가 뜨는지까지는 확인해도 되지만 **로그인은 하지 마라**.
