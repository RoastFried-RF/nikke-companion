작업 ID: P-021
제목: 오버레이: 인식한 요격전 보스의 추천을 자동으로 보여 주기 + 중복 실행 방지
설명: 게임에서 이상 개체 요격전 화면(보스 선택·편성)을 보고 있으면 오버레이가 그 보스의 추천 편성을 스스로 보여 준다. P-019의 인식(recognize.rs, 앱 명령 recognize_game_screen)과 P-017의 요격전 화면(InterceptScreen)을 잇는다. 게임 창 추적 스레드(lib.rs의 track_game)가 이미 있다 — 인식도 Rust 쪽에서 주기적으로 돌리고 결과가 바뀔 때만 화면에 이벤트로 알린다. 게임은 읽기만 한다(P-011과 같은 규칙: 입력·창 조작·메모리 접근 없음). 캡처한 이미지는 저장하지도 화면에 넘기지도 않는다. 덧붙여 결함 하나를 고친다: 오버레이를 두 번 실행하면 두 번째 창이 단축키 등록 실패 오류를 띄운다 — 이미 실행 중이면 두 번째 실행은 조용히 끝나고 기존 창을 보이게 한다(게임 포커스를 뺏지 않는 P-016의 보이기 방식으로).

수락 조건:
- 자동 추적 켜기/끄기: 요격전 화면에 스위치가 있고 상태를 기억한다(기본 꺼짐). 켜져 있고 게임 창이 떠 있을 때만 주기적으로(기본 2초, 설정 가능) 게임 화면을 읽어 인식한다. 꺼져 있거나 게임이 없거나 최소화돼 있거나 오버레이가 숨겨져 있으면 캡처하지 않는다
- 인식 결과가 이상 개체 화면 + 보스이면: 오버레이가 요격전 탭이 아니어도 요격전 탭으로 옮기고(이 자동 이동도 끌 수 있다) 그 보스를 고른다. 추천 결과가 이미 있으면 그 보스의 편성이 바로 보인다. 결과가 없으면 "추천을 먼저 실행하라"는 안내가 보인다 — 자동으로 계산을 시작하지 않는다
- 인식 결과가 unknown이거나 other이면 고른 보스를 바꾸지 않는다(마지막 보스 유지). 같은 결과가 이어지는 동안에는 화면을 다시 건드리지 않는다 — 사용자가 손으로 다른 보스를 고르면 인식 결과가 바뀔 때까지 그대로 둔다
- 화면에 인식 상태가 보인다: 지금 인식한 화면·보스, 마지막으로 읽은 시각, 인식 못 함/게임 없음 같은 이유. 틀린 인식을 알아챌 수 있게 근거 한 줄을 펼쳐 볼 수 있다
- 연속 캡처가 실패하면(게임 종료·최소화·캡처 오류) 오류를 쌓지 않고 상태로만 보이며, 게임이 다시 뜨면 스스로 이어진다. 추적 스레드가 죽지 않는다
- 상태 전환 규칙(언제 보스를 바꾸고 언제 그대로 두는지)은 순수 함수로 두고 단위 테스트한다(Rust 또는 TS 한쪽에). 화면 테스트(가짜 backend): 인식 이벤트가 오면 탭·보스가 바뀌고, unknown에서는 안 바뀌고, 손으로 고른 보스가 유지되고, 스위치를 끄면 이벤트를 무시한다
- 캡처 주기 동안 캡처 한 번에 걸리는 시간을 재서 app/README.md에 적는다. 캡처할 때마다 Direct3D 장치와 세션을 새로 만들어 느리다면 그 사실과 측정값을 적는다(재사용은 필요하면 하되 P-011의 테스트가 계속 통과해야 한다)
- 중복 실행 방지: 두 번째 실행은 창을 만들지 않고 끝난다. 기존 창이 숨겨져 있었다면 보이게 한다. 단위 테스트 또는 실행 파일을 두 번 띄우는 통합 테스트로 확인한다(화면이 필요한 테스트는 #[ignore]로 두고 README에 명령을 적는다). capability에는 새로 쓰는 것만 더한다
- 기존 테스트가 계속 통과하고 cargo clippy --all-targets에 경고가 없다. app/README.md와 루트 CLAUDE.md를 갱신한다
